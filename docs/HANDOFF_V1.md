# HANDOFF_V1 — 개발 방 착수 지시서

> 이 문서는 개발 담당 Claude가 **처음 읽는 문서**다. 저장소 `jihoon380462/Business_Sim`을 연결한 뒤 이 파일부터 읽고 시작한다.

## 1. 당신의 역할
- 당신은 **개발 담당**이다. 기획은 별도 채팅(기획 방)이 맡는다. 두 방은 서로의 대화를 볼 수 없다.
- 당신이 수정하는 폴더: `src/`, `tests/`, `index.html`, `assets/placeholder/`. 나머지는 읽기만 한다.
- 기획 문서에 없는 것을 정해야 하면 **일단 합리적으로 정해서 진행**하고, `docs/REQUESTS.md`에 `[개발→기획]` 항목으로 기록한다. 기획 답변을 기다리며 멈추지 않는다.
- 아트 에셋은 당신이 주문하지 않는다. 필요한 에셋은 `REQUESTS.md`에 파일명·크기·용도만 적는다. 그 전까지는 `assets/placeholder/`에 같은 파일명으로 회색 박스를 두고 진행한다.

## 2. 반드시 읽을 문서 (순서대로)
1. `docs/SCOPE_V1.md` — **이번에 만들 것의 전부.** 여기 없는 기능은 만들지 않는다.
2. `docs/UI_SPEC_V1.md` — 화면별 레이아웃·컨트롤·상태. 레퍼런스 이미지는 `art/reference/REF-main-M.png`와 `art/reference/screens/`
3. `docs/REPO_STRUCTURE.md` — 폴더 구조, core/ui 분리 규칙, 데이터 규칙, 브랜치 규칙
4. `docs/GDD.md` — 전체 비전. V1 설계가 V2 이후를 막지 않도록 참고만 한다. V1에 넣지 않는다.
5. `docs/REQUESTS.md` — 열린 요청이 있으면 확인
6. `docs/DECISIONS.md` — 기획이 이미 확정한 결정 목록

## 3. 기술 조건
- 순수 HTML + CSS + JS. 빌드 도구·프레임워크 없음. 로컬 서버(`python -m http.server`)나 GitHub Pages로 열면 바로 실행. (ES 모듈·fetch 때문에 Chrome에서 file:// 더블클릭은 안 됨)
- ES Modules (`<script type="module">`). 외부 라이브러리 없음.
- 세로 모바일 전용. 논리 해상도 360×640 기준, 더 긴 화면은 세로로 늘어남. 가로 모드 대응 안 함.
- 데이터는 `src/data/*.json`을 `fetch`로 읽는다. **코드 안에 밸런스 숫자 리터럴 금지.**
- `src/core/`는 `document`·`window`·DOM을 참조하지 않는다. 모든 공개 함수는 `(state, input) → newState`. 이 규칙은 나중에 Unity(C#) 이식을 위한 것이므로 예외 없음.
- 저장: `localStorage`, 키 `business_sim_save`, `state.version` 포함.
- 난수: `src/core/rng.js`의 시드 난수만 사용. `Math.random()` 직접 호출 금지(테스트 재현용).
- **시간 진행은 실시간.** `ui`가 `setInterval`(또는 `requestAnimationFrame` 누적)로 주 길이(`config.json`의 `weekDurationMs`, 초안 4000)마다 `core.advanceWeek(state)`를 호출한다. core는 타이머를 모른다.
- **창이 열리면 일시정지.** 모든 창(탭·팝업)은 하나의 모달 매니저를 거치고, 열릴 때 타이머 정지·닫힐 때 재개. 속도 버튼(⏸ ▶ ▶▶)은 별도 상태. 앱 재진입 시 항상 일시정지로 시작.
- 탭이 백그라운드로 가면(`visibilitychange`) 일시정지. 돌아왔을 때 몰아서 진행하지 않는다.

## 4. 작업 순서
각 단계 끝날 때마다 `main`에 커밋하고, `index.html`이 열리는 상태를 유지한다.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 0 | 뼈대 | `index.html` + `src/main.js` + 빈 화면 5개 탭 전환, `config.json` 로드 |
| 1 | 시간·돈 | 타이머로 주차 자동 증가, 주 진행 게이지, 속도 버튼 3종, 창 열림=정지, 생활비 차감, 알림 피드 |
| 2 | 알바 | 활동 창에서 알바 3종/휴식 설정, 매주 주급·체력 반영, 체력 0 → 자동 휴식, 잔액 음수 → 강제 알바 |
| 3 | 주식 | 5종목 가격 변동, 매수/매도, 수수료, 보유 현황 |
| 4 | 대출 | 한도·이자, 상환 |
| 5 | 사업 | 노점 개업 → 분식집, 운영 방침(가격·재료·홍보·휴무) 설정값, 평판, 직원 1명 |
| 6 | 이벤트 | 8종, 통보형은 피드·선택형은 팝업+정지, 소문→뉴스, 상장폐지 |
| 7 | 저장 | 자동 저장(매주+창 닫을 때), 재진입 시 일시정지, 이어하기/새로하기 |
| 8 | 마감 | V1 종료 조건(4주 연속 흑자) → 결산 리포트 창, 15분 플레이 테스트, `tests/`에 core 검증 |

## 5. 커밋 규칙
- 메시지 형식: `[단계N] 한 줄 요약` (예: `[단계3] 주식 매수/매도 구현`)
- 한 단계 = 한 커밋 이상. 단계 중간에 저장소가 안 열리는 상태로 커밋하지 않는다.

## 6. 끝나면
- `docs/REQUESTS.md`에 `[개발→기획]`으로 **V1 완료 보고** 1건: 실제 플레이 시 노점 개업 주차, 분식집 개업 주차, 느낀 문제점 3개.
- 기획 문서와 다르게 구현한 부분이 있으면 전부 같은 항목에 적는다.
