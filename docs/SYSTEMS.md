# 시스템 뼈대 (SYSTEMS)

> **구조 문서.** GDD가 "무엇을 느끼게 할 것인가"라면 이 문서는 "게임이 어떤 부품으로 돌아가는가"다.
> 원칙: **시스템은 코드, 콘텐츠는 데이터.** 여기 정의된 틀 안에서 콘텐츠(업종·활동·인물·이벤트)는 `src/data/*.json`에 행을 추가하는 것으로 들어간다. 코드 수정 없이 콘텐츠가 늘어나지 않으면 틀이 잘못된 것이다.
> 비어 있는 칸은 `(슬롯)`으로 표시. 채우는 양식은 `docs/CONTENT_TEMPLATES.md`.

## 0. 전체 그림

```
주인공 ──스탯·컨디션·경력──┐
                          │ 매달 슬롯에 시간을 배분
활동 ◄────────────────────┤
  ├─ 알바 ───────► 자금
  ├─ 가게 운영 ──► 사업체 ──► 자금, 평판, 경력
  ├─ 자기계발 ──► 스탯, 자격
  └─ 사람 만나기 ► 관계 ──► 사업 효과, 엔딩
금융 (주식·대출·부동산) ◄──► 자금
이벤트 ──► 위 전부를 흔든다 (확률 + 조건)
성장 단계 ──► 해금: 업종, 슬롯 수, 기능, UI 테마
30년 ──► 엔딩 = f(자산, 관계, 평판)
```

모든 수치 흐름은 **자금** 하나로 모이고, 모든 선택은 **슬롯(시간)** 하나에서 갈라진다. 이 두 병목이 게임의 긴장이다.

## 1. 시간과 턴

- 1턴 = 1개월. 1년 = 12턴. 게임 = 30년 = 360턴. 표기 `N년차 M월`. 나이 = 20 + (N−1).
- 계절 3개월 단위. 계절은 업종 매출·이벤트 가중치에만 영향.

### 턴 파이프라인 (`advanceMonth` 내부 순서, 고정)
| 순서 | 단계 | 하는 일 |
|---|---|---|
| 1 | 입력 확정 | 슬롯 선택, 사업 방침, 미처리 즉시 행동(매매·대출·개업)은 이미 반영됨 |
| 2 | 활동 결산 | 본업·여가 효과: 수입, 컨디션, 스탯 상승, 경력 누적 |
| 3 | 사업 결산 | 사업체마다 매출·비용·순익·평판 변화, 직원 상태 |
| 4 | 금융 결산 | 주가 변동, 배당, 대출 이자, 부동산 임대료·가치 |
| 5 | 생활비 | 단계별 생활비 차감 |
| 6 | 관계 결산 | 호감도 자연 변화, 만남 효과, 관계 단계 판정 |
| 7 | 이벤트 | 조건·확률로 1~2건 선택. 통보형 즉시 적용, 선택형은 큐에 |
| 8 | 단계 판정 | 성장 단계 진입 조건 검사 → 해금 |
| 9 | 엔딩 판정 | 30년차 12월 또는 5단계 트리거 |
| 10 | 기록·저장 | 결산 요약 생성, 피드 기록, 자동 저장 |

> 새 시스템이 생기면 이 표의 어느 단계에 끼는지부터 정한다. 단계를 늘리지 않는다.

## 2. 주인공

### 2.1 스탯 (5개, 0~100) — 고정, 늘리지 않음
| 스탯 | 뜻 | 올리는 활동 유형 | 영향 공식 (기본형) |
|---|---|---|---|
| 체력 | 몸 | 육체 노동, 운동 | 컨디션 최대치 = 체력 |
| 기술 | 만드는 것의 품질 | 현장 노동, 직접 운영, 공부 | 사업 매출 배율 `0.85 + 0.3×기술/100`, 업종별 2차 효과(불량률 등) |
| 경영 | 조직·돈 다루기 | 직접 운영, 공부 | 고정비 `×(1 − 0.15×경영/100)`, 직원 효율, 위임·법인 해금 |
| 화술 | 사람 다루기 | 접객, 만남 | 대출 이자 `×(1 − 0.4×화술/100)`, 협상, 호감도 상승 배율 |
| 지식 | 정보·판단 | 공부, 자격 | 소문 정확도, 상위 업종·상장 해금, 주식 수수료 할인 |
- 상승 규칙: 활동마다 `statGain {스탯: +n}`. 90 이상 절반. 하락은 없음(V3에서 노화 검토).
- 모든 배율은 **선형**, 스탯 50 = 1.0배 근처로 맞춘다. 업종별 특수 효과는 공식을 바꾸지 않고 `2차 효과` 칸에 추가.

### 2.2 컨디션
- 0~체력. 활동이 깎고 휴식이 채운다. 0 → 다음 달 본업 강제 휴식. 30 이하 → 운영 매출 ×0.8.
- (슬롯) 3단계 이후 "과로 누적" 같은 장기 상태는 여기 확장.

### 2.3 경력·자격 (V2)
- **경력** = 활동 태그별 누적 개월. `career { 요식: 14, 유통: 0, 접객: 20, 경영: 6 … }`. 활동 데이터에 `careerTag`만 붙이면 자동 누적.
- **자격** = 취득형 플래그. 조건(스탯·경력·비용·시험 이벤트) → 효과(업종 해금, 배율). `(슬롯)` 목록은 CONTENT_TEMPLATES.
- 쓰임: 업종 개업 조건, 평판 시작값 보너스, 특정 이벤트 선택지.

### 2.4 그 외
- 성별 2종(표시·대사 톤만, 수치 차이 없음). 이름 입력. (슬롯) 출신·배경 선택은 V3 검토.

## 3. 활동 시스템

### 3.1 슬롯 모델
| 단계 | 슬롯 | 비고 |
|---|---|---|
| 0~2 | 본업 1 + 여가 1 | V1 |
| 3~4 | 본업 1 + 여가 1 + **경영 일정 1** | 경영 일정: 지점 순회, 회의, 투자 검토, 인재 면접 |
| 5 | 경영 일정 2 + 여가 1 | 본업 개념이 사라짐(회장) |
- 슬롯은 매달 유지(바꾸기 전까지). 슬롯 종류는 3개로 고정하고 **활동이 어느 슬롯에 들어가는지**만 데이터로 정한다.

### 3.2 활동 데이터 스키마 (공통)
```
id, slot(main|leisure|exec), name, 
unlock { stage, stat{}, career{}, business, item },
cost(월 비용), income { base, statKey } (= base × (0.8+0.4×stat/100)),
condition(±), statGain {}, careerTag,
businessEffect (운영형: operate|delegate|none),
relationEffect (만남형: targetSelect, affinityGain)
```
### 3.3 활동 카테고리와 슬롯 현황
| 카테고리 | 슬롯 | V1 | 목표 개수 | 비고 |
|---|---|---|---|---|
| 알바 | 본업 | 편의점·택배·카페 | 8~10 | 업종별 경력 태그를 고루 |
| 가게 운영 | 본업 | 직접 운영 | 1 (사업체 수만큼 자동) | |
| 위임 | 본업 | 위임 | 1 | 조건: 직원·경영 |
| 자기계발 | 여가 | 공부 | 4~6 | 학원·자격 시험 준비·독서 `(슬롯)` |
| 운동 | 여가 | 헬스장 | 2~3 | 러닝·수영 등 `(슬롯)` |
| 관계 | 여가 | — | 1 (대상 선택식) | V2 "사람 만나기" |
| 휴식 | 여가 | 휴식 | 1~2 | 여행(돈 쓰고 큰 회복) `(슬롯)` |
| 경영 일정 | 경영 | — | 4~6 | V3 |

## 4. 사업 시스템

### 4.1 사업체 공통 모델 (모든 업종이 같은 필드)
```
id, type(업종 id), name, stage(0~5 중 해당), 
openCost, revenueMin/Max, fixedCost, 
qualityGrades {1,2,3: costRate, repDelta}, upgradeCosts,
promoCost, seasonMult{}, 
staffModel { wage, revenueMult, maxStaff, managerUnlock },
operate { ownerRequired, delegateMult },
statHooks { revenue: 기술, cost: 경영, extra: (업종별 2차 효과 키) },
unlock { stage, requiresBusiness, capital, career, cert },
upgradeTo(다음 단계 사업체 id)
```
- 매출 공식(공통): `기대치 × 평판배율 × 가격배율 × 계절 × 기술배율 × 운영형태 × (2차 효과)`
- 비용 공식(공통): `재료(매출×등급비율) + 인건비 + 고정비×경영배율 + 홍보 + 이자`
- 평판 0~100 사업체별. 월 변화 = 가격·재료·홍보·주인 부재·이벤트.

### 4.2 업종 트리 (슬롯 테이블)
| 업종 | 0~1단계 | 2단계 | 3단계 | 4단계 | 5단계 | 2차 효과 키 |
|---|---|---|---|---|---|---|
| 요식 | 노점 | 분식집 | 카페·레스토랑 `(슬롯)` | 프랜차이즈 본사 `(슬롯)` | 외식 그룹 `(슬롯)` | 재료 등급·위생 |
| 유통 | — | 편의점 `(슬롯)` | 마트 `(슬롯)` | 물류센터 `(슬롯)` | 유통 그룹 `(슬롯)` | 재고 손실률 |
| IT | — | 쇼핑몰 `(슬롯)` | 앱 서비스 `(슬롯)` | 플랫폼 `(슬롯)` | IT 그룹 `(슬롯)` | 장애율·사용자 수 |
| 제조 | — | — | 소규모 공장 `(슬롯)` | 공장 2~3개 `(슬롯)` | 제조 그룹 `(슬롯)` | 불량률·설비 |
| 부동산 | — | — | 상가 1채 `(슬롯)` | 건물 `(슬롯)` | 개발사 `(슬롯)` | 공실률·가치 상승 |
- 업종 추가 = 이 표에 행 추가 + `businesses.json`에 사업체 타입 추가. 2차 효과 키가 새로우면 그때만 코드 1함수.
- **사업체 여러 개** 보유는 3단계부터. `state.businesses[]` 배열, V1부터 배열로 만든다.

### 4.3 직원·조직
| 단계 | 모델 |
|---|---|
| 2 | 직원 n명: 급여, 매출 배율. 사기 없음 |
| 3 | 직원 속성(능력·급여·사기) + **매니저**(위임 자동화, 경영 스탯 조건) |
| 4 | 임원: 부문별 자동 운영, 인재 영입 이벤트, 경쟁사 스카우트 |
- 데이터: `staff { id, name, skill, wage, morale, role }`. V1은 `role: staff` 1명만 생성하되 구조는 배열.

### 4.4 법인·확장·상장
- 3단계 **법인 설립**: 순자산 조건 + 경영 스탯. 효과: 사업체 다수 보유, 은행 대출 한도 ↑, 세금 `(슬롯)`.
- 확장: `upgradeTo` 체인 또는 신규 개업. 인수(M&A)는 4단계: 경쟁 NPC 기업을 자금으로 흡수.
- 5단계 **상장(IPO)**: 지식·경영·순자산 조건 → 내 회사가 주식 종목에 추가, 자금 유입, 주가 = 실적 연동. 엔딩 트리거.

## 5. 금융 시스템

### 5.1 자금과 생활비
- 자금 단일 계정. 생활비는 **단계별 상수**(0~2: 60만, 3: 150만, 4: 400만, 5: 1,000만) — 잘 살수록 돈이 샌다는 압박 유지. `(슬롯)` 결혼·가족 시 가산.

### 5.2 대출과 신용
- 신용 0~100 (V2). 한도 = 기본 × 단계 × 신용. 이자 = 기본 × 화술 할인 × 신용 할인. 연체(자금 < 0 지속) → 신용 하락, 강제 매각 이벤트 `(슬롯)`.
- 대출 상품은 데이터: `{ id, unlockStage, limitBase, rate, term }`. V1은 1종.

### 5.3 주식
- 종목 모델: `{ id, name, sector, volatility, drift, dividendRate, listed }`. 섹터 추세 + 종목 랜덤 + 뉴스 충격.
- 섹터 5개(식품·IT·건설·바이오·엔터) `(슬롯)` 종목 10~15개까지. 5단계 내 회사 종목 자동 추가.
- 정보 계층: 소문(선택형 이벤트) → 뉴스(실현). 지식 스탯이 정보량 결정. `(슬롯)` 3단계 증권사 NPC 정보원.
- 상장폐지·유상증자·배당은 **종목 속성 + 이벤트**로, 코드는 공통.

### 5.4 부동산 (V3)
- 자산 모델: `{ id, price, rentPerMonth, valueDrift, vacancyRate }`. 매달 임대료 + 가치 변동. 사업체 입지로도 쓰임(임대료 vs 자가).

### 5.5 세금 (옵션, V3 검토)
- 연 1회 12월 결산 이벤트. 법인 여부로 세율. 재미보다 "연말 정산 리듬"용. 끌 수 있게 `config.tax.enabled`.

## 6. 사람 시스템

### 6.1 인물 공통 모델
```
id, name, gender, role(romance|partner|staff|rival|mentor), 
appearStage, appearCondition(활동·업종·이벤트),
portraitSet(7종), personality(태그 3개), moneyValue(돈에 대한 가치관),
affinity 0~100, relationStage, 
hooks { businessEffect[], eventIds[], endingTag }
```
- **연애 대상은 role만 다르다.** 거래처·멘토·라이벌도 같은 모델, 같은 호감도. 콘텐츠 추가 = `characters.json` 행 추가.

### 6.2 관계 단계와 역학
| 단계 | 호감도 | 해금 |
|---|---|---|
| 지인 | 0 | 등장 |
| 친구 | 30 | 전용 이벤트 1, 소소한 도움 |
| 호감 | 60 | 전용 이벤트 2, 정보·할인 |
| 연인 | 80 + 고백 이벤트 | **사업 효과 발동**(인맥 대출, 직원 추천, 거래처 조건) |
| 결혼 | 100 + 조건(자금·주거) | 배우자 효과 지속, 생활비 변화, 가족 이벤트 `(슬롯)` |
- 상승: "사람 만나기" 슬롯(대상 선택) + 화술 배율. 하락: N개월 미접촉 시 −2/월, 연인 이상에서 바람 이벤트.
- 사업 효과는 **훅 목록**으로 데이터화: `{ type: loanLimit|staffRecommend|supplierDiscount|stockTip|reputation, value }`.

### 6.3 가족 (미결 → 결정 시 여기)
- `(슬롯)` 자녀: 생활비 가산 + 이벤트 라인 + 엔딩 변수. 포함 여부 DECISIONS 미결.

## 7. 이벤트 시스템

### 7.1 종류
| 종류 | 처리 | 예 |
|---|---|---|
| 통보형 | 결산 요약에 한 줄, 즉시 적용 | 병원비, 단골 |
| 선택형 | 팝업 2~3지선다 | 소문, 거래 제안 |
| 연쇄형 | 선택 결과가 N개월 뒤 후속 이벤트 | 소문 → 뉴스, 투자 제안 → 결과 |
| 세계 이벤트 | 전역 배율 N개월 지속 | 불황, 호황, 전염병, 금리 변동 |

### 7.2 이벤트 데이터 스키마
```
id, kind, category(life|stock|business|relation|world), 
trigger { chance, cooldown, stage[], condition(식) }, 
text, choices[{ id, label, effects[], followUp{ eventId, delay } }],
effects[ { target: money|condition|stat|reputation|affinity|stockShock|worldMult, value } ]
```
- `condition`은 단순 비교식 문자열(`business.type == 'snackbar' && stats.management < 30`). 평가기 1개로 모든 조건 처리.
- 월 최대 1건(세계 이벤트는 별도 1건). 단계별 풀 가중치.

### 7.3 세계 이벤트 (경기 사이클)
- 5~10년 주기 큰 것 1개 + 1~2년 작은 것. 효과: 업종 매출 배율, 주식 섹터 드리프트, 대출 금리. `(슬롯)` 목록.
- 목적: 현금 비중·안전 자산·업종 분산에 의미 부여.

## 8. 성장 단계와 해금

| 단계 | 호칭 | 진입 조건 | 해금 |
|---|---|---|---|
| 0 | 알바생 | 시작 | 알바, 주식, 여가 |
| 1 | 노점상 | 노점 개업 | 대출 |
| 2 | 사장 | 가게(분식집급) 개업 | 직원, 위임, 상위 업종 2단계 |
| 3 | 법인 대표 | 사업체 2개 + 순자산 2억 + 경영 40 | 법인, 경영 일정 슬롯, 매니저, 부동산, 업종 3단계 |

- 해금은 **테이블 1개**(`stages.json`)로. 기능·업종·슬롯·UI 테마·생활비·주인공 의상·배경이 전부 단계 키로 조회.

## 9. 엔딩

- 판정 시점: 30년차 12월 결산 후, 또는 5단계 진입 시 "지금 은퇴 / 계속" 선택.
- 3축: 자산 등급(A~F, 순자산 구간) × 관계(독신/연인/기혼/이혼/사별) × 평판(존경/보통/악덕 — 평균 평판·악행 이벤트 선택 수).
- 엔딩 = 3축 조합 → `endings.json`에서 가장 구체적인 매칭 1개. `(슬롯)` 목표 12~16개. 특수 엔딩(파산·과로사 등)은 조건 우선.
- 화면: 결산 리포트 확장판(30년 그래프) + 엔딩 일러스트 1장 + 업적.

## 10. 경제 밸런스 프레임

- 단계별 **자금 규모 자릿수**: 0단계 백만 / 1~2 천만 / 3 억 / 4 십억 / 5 천억. 각 단계의 모든 수치(매출·비용·대출·생활비·이벤트 금액)는 그 자릿수 안에서 움직인다. 자릿수가 바뀌면 UI 표기도 `만 → 억` 자동 전환.
- 체류 목표: 0단계 4~6개월 / 1단계 ~1년 / 2단계 2~3년 / 3단계 5년 / 4단계 8년 / 5단계 나머지.
- 검증: 모든 밸런스 변경은 **20시드 봇 시뮬**(전략 3종: 사업·주식·혼합)로 단계 진입 월을 확인. 봇은 `tests/`에 상주.
- 주식은 어떤 단계에서도 사업 수익의 30%를 넘지 않게. 넘으면 변동폭·상폐 확률로 조정.

---

## 11. UI 뼈대

- 탭 5개 고정: 활동 · 주식 · 사업 · 나 · 설정. 늘리지 않는다. 새 기능은 **창 안의 하위 탭**으로.
  - 나 창: 스탯 / (V2) 사람 / (V2) 경력·자격
  - 사업 창: 사업체 목록 → 선택 → 운영. (V3) 법인 / 부동산 하위 탭
  - 주식 창: 종목 / (V3) 포트폴리오·뉴스
- 창 패턴 3종만 쓴다: **리스트 선택형**(활동·개업), **운영 패널형**(사업), **표형**(결산). 새 화면은 셋 중 하나로.
- 단계 진급 시: 메인 배경·주인공 의상·테마 색 교체. 모두 `stages.json`에서 조회.
